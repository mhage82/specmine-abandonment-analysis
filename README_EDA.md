# Data Quality and Exploratory Analysis

This is an add-on to the existing group project, not a replacement repository.
It reads the Parquet analysis table generated by data loader and writes descriptive
quality summaries, exploratory tables, two figures, and a findings document.
It does not edit inputs, drop records, impute values, or assign abandonment labels.


## Run from CMD

Install the dependencies once:

```bat
python -m pip install -r requirements-eda.txt
```

The only new direct dependency beyond items 6/7 is matplotlib. NumPy is already
installed through pandas/matplotlib. The group can merge these requirements
into its existing requirements.txt later rather than maintain two lists.

If `results/analysis_table.parquet` already exists from a successful data loader run,
you can proceed directly to EDA. Otherwise, generate it first:

```bat
python src/feature_pipeline.py --data-dir data/specmine-official/data --output-dir results
```

Then run exploratory analysis:

```bat
python src/exploratory_analysis.py
```

Expected console output for the reference sample:

```text
Analyzed 28,583 specification rows.
Tables and findings: results/eda
Figures: figures/eda
```

Windows may display backslashes in these paths. For a custom input location:

```bat
python src/exploratory_analysis.py --input "C:\path\to\analysis_table.parquet" --output-dir results/eda --figures-dir figures/eda
```

This script does not download data or rerun data loader automatically. Use the Parquet
output, not the CSV. An empty table or absent required columns produces an error.
Rerunning replaces outputs with the same names. It never commits or pushes files.

## Outputs

| File in `results/eda/` | Purpose |
| --- | --- |
| `missingness.csv` | Null count and percentage for every input column |
| `quality_checks.csv` | Missing/duplicate keys, invalid counts/flags, date-order problems, unmatched feature/history flags |
| `date_coverage.csv` | Earliest/latest valid dates and missing/invalid counts for observed history endpoints |
| `numeric_summary.csv` | Count, mean, standard deviation, min, quartiles, max for numeric input columns |
| `indicator_summary.csv` | TODO, placeholder, and unchecked-checkbox counts, denominators, unknown counts, and percentages |
| `tool_distribution.csv` | Number of specification rows by tool attribution |
| `commit_distribution.csv` | Observed distinct commits grouped as 0, 1, 2, 3–5, 6–10, or 11+ |
| `eda_summary.json` | Overall counts, checks with findings, input fingerprint, and software versions |
| `findings.md` | Generated measured findings, interpretation limits, and follow-up actions |

The two PNG figures in `figures/eda/` visualize unfinished-work indicators and
observed commit-count distribution.

## Definitions

- TODO indicator: `feature_n_todo > 0`, provided the count is a nonnegative integer.
- Placeholder indicator: `feature_has_unfilled_placeholder == 1`; only 0/1 values are valid.
- Unchecked-checkbox indicator: `feature_n_checkboxes > feature_n_checked`.
  Both must be nonnegative integers, and checked must not exceed total.
- Percentage denominator: records with valid observed values for that indicator.
  Missing/invalid values are reported as unknown, not treated as negative cases.
- Groups overlap. Do not add the three positive counts into a unique total.
- The checkbox measure is an observable proxy, not a verified count of unfinished tasks.
- Numeric summaries describe stored columns, including identifiers if numeric;
  they are not a selected predictor list or correlation/model analysis.
- Quality-check counts can overlap and must not be summed into unique bad rows.

## Limitations


The source input fingerprints are included in `reference_results/source_pipeline_summary.json`.
The combined Parquet fingerprint is recorded in the EDA summary. A Parquet
byte fingerprint can change across writer versions even when logical table
values agree; retain package versions when comparing reproducibility.

The reference sample has 28,583 specs from 415 repositories. The source's
500-repository sample also includes other layers; this analysis covers only
the broad-census input selected. It is curated, not representative.

Missingness measures nulls, not every form of semantic absence. No implemented
consistency check finding does not mean there are no data-quality limitations.
Commit histories may be incomplete, feature extraction may have failed even
when a row exists, and inactive specs may be complete. Inspect source cases
and statuses before final outcome definitions. No inactivity/censoring threshold
is silently assumed. Read the original pipeline summary for upstream join issues.

## Tests and team review

```bat
python -m unittest discover -s tests -p test_exploratory_analysis.py -v
```

Two focused tests verify that unknown/invalid indicators are excluded from
denominators and that an all-unknown indicator has an undefined percentage.
